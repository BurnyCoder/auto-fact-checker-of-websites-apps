# Summary of all experiments

Author: Libor "Burny" Burian · 2026-11-08 · Every number below is generated by `uv run python -m eval.report` from
`results/`.

## In plain words

We built an app that reads what is on your screen — web pages through a Chrome extension, anything else through
Windows' built-in text recognition — picks out factual claims, and asks an AI agent (Claude Haiku 5.5) to check each
one by searching the web, reading pages, downloading data and running small calculations. Every check returns a verdict
(true / false / not enough evidence / misleading), how sure the agent is and why, the sources it used, and a corrected
statement when the claim is false.

We then measured, on public benchmarks of real fact-checked claims, (1) whether the web tools make the agent more
accurate than answering from memory, (2) how much of that comes from simply finding an existing fact-check article,
(3) whether reading text from the screen through OCR loses accuracy compared with having the exact text, and (4)
whether the claim-picking step finds the sentences professional fact-checkers consider worth checking. All experiments
ran under a $10 cap on model usage (raised to $20 afterwards for using the app), which caps the number of claims we could test and therefore how small an effect we
can detect.

## Glossary

* **Claim / atomic claim** — one checkable statement; *atomic* = cannot be split further; *self-contained* = understandable
  without the surrounding text (pronouns resolved).
* **Check-worthy** — a claim a professional fact-checker would consider worth checking (CheckThat! definition).
* **AVeriTeC labels** — *Supported*, *Refuted*, *Not Enough Evidence* (NEE), *Conflicting Evidence/Cherry-picking*
  (evidence both ways, or technically true but misleading).
* **Closed-book** — the model answers from what it learned in training, without web access (it can still compute).
* **Leakage** — the agent finding the benchmark's answer (e.g. the dataset file or the fact-check the claim came from)
  instead of checking the claim; controlled with blocklists and an audit.
* **Accuracy** — share of claims with the right label. **Macro-F1** — average of per-label F1, so rare labels count as
  much as common ones. **F1** — harmonic mean of precision (how many flagged items are right) and recall (how many
  right items are flagged).
* **McNemar test** — compares two systems on the same items using only the items where exactly one is right.
* **Bootstrap CI** — uncertainty interval from re-sampling the claims with replacement 10,000 times.
* **Holm correction** — adjusts p-values when several hypotheses are tested, so the chance of any false positive stays ≤ 5 %.
* **Non-inferiority** — showing a new condition is *not worse than* a reference by more than a chosen margin (here 3 points).
* **MDE** — minimum detectable effect: the smallest true difference the study had an 80 % chance to detect.
* **Calibration / Brier / ECE** — whether stated confidence matches observed accuracy; Brier = mean squared error of the
  confidence; ECE = average gap between confidence and accuracy across confidence bins.
* **CER / WER** — character / word error rate of OCR text vs the true text.
* **Fleiss' κ** — agreement between repeated runs beyond chance (1 = identical, 0 = chance).
* **API-equivalent cost** — what the calls would cost on the pay-as-you-go API; most calls were billed to a subscription.
